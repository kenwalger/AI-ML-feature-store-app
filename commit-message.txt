Fix PostgreSQL driver installation and database connection initialization

This commit fixes the runtime error where SQLAlchemy couldn't load the
PostgreSQL dialect plugin, and improves database connection handling
with lazy initialization and better error handling.

Runtime Fixes:
- Implement lazy initialization for database engines to handle missing
  psycopg2-binary gracefully
- Add error handling for database connection creation
- Fix postgres:// to postgresql:// URL conversion for SQLAlchemy 2.0
- Update all database engine references to use lazy initialization
  functions

Database Connection Improvements:
- Create engines lazily only when needed (not at module import time)
- Add defensive error handling for missing database URLs
- Improve follower database availability checking
- Update metrics service to handle missing engines gracefully
- Update toggle endpoint to properly check follower availability

The issue was that database engines were being created at module import
time, which caused failures if psycopg2-binary wasn't installed or
DATABASE_URL wasn't set. With lazy initialization, the app can start
even if the database isn't immediately available, and will create
connections when actually needed.

This should resolve the "Can't load plugin: sqlalchemy.dialects:postgres"
error by ensuring psycopg2-binary is properly required and connections
are created only when the database is actually needed.
